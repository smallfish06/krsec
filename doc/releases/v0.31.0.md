# v0.31.0

A hardening release. It fixes orders that could be sent on the wrong side, order states that were inferred instead of read, and several ways the gateway's shared state could be changed or exposed by a single HTTP request. It also adds an optional gateway API key.

## Upgrade notes

- **Order validation:** `side` must be `buy` or `sell` and `type` must be `limit` or `market` (case-insensitive over HTTP). KIS and Kiwoom previously sent any other side as a buy. Options a broker cannot honor are rejected instead of dropped: fractional or amount-based quantities and non-day time-in-force on KIS and Kiwoom.
- **`POST /auth/token`:** a configured account authenticates only with its configured credentials. The request's `credentials` may be omitted; when present they must match, otherwise the response is 401. Previously the supplied key pair was written onto the shared adapter before it was validated.
- **Raw proxy `account_id`:** the documented `?account_id=` query parameter now selects the account on `/kis`, `/kiwoom`, `/ls` and `/toss` routes. It was ignored on all but the static Kiwoom routes, so requests fell back to the first account. A body `account_id` that disagrees with the query is a 400.
- **KIS order status:** `GET .../orders/{id}` reads the order history instead of inferring a fill when the order is missing from the open-order list, and returns an error when the lookup fails. The order-history lookup previously sent an invalid `tr_id` and always failed.
- **Kiwoom order status:** lookup failures are returned instead of the cached status; an order closed after a partial fill is `cancelled` with its filled quantity, not `filled`.
- **LS response codes:** `rsp_cd` values `00000`-`00999` are treated as success, matching LS's message-code ranges. Only `00000` was accepted before, so every `CSPAQ*` account query failed with 502: `CSPAQ12200` answers `00136` and an empty `CSPAQ13700` answers `00200` (both observed on the live API). Business rejections (`01000`-`07999`) map to 400 instead of 502. Accepted orders are reported to answer `00040`/`00039`; **order placement was not exercised, so place one order deliberately before relying on it.**
- **LS balance and positions:** these failed with "invalid LS response continuation flag" because `t0424` answers `tr_cont: 0`. Only `Y` now means another page; every other value ends paging.
- **LS overseas candles:** `g3204` returns up to 500 rows per request (observed live), not 5. The default is 100, and the start date is left open when `from` is omitted instead of being pinned to one month back.
- **Toss modify:** a modify without `type` and without `price` is rejected. It was previously sent as a market order. Order placement generates a `clientOrderId` when none is given and returns it as `client_order_id`.
- **Timestamps:** KIS and Kiwoom order and fill times are interpreted as KST regardless of the process time zone. Under UTC they were nine hours off, and Kiwoom token expiry was believed nine hours later than it was.
- **Config:** `server.host` and `server.port` default to `localhost` and `8080`. `server.api_key` / `server.api_key_env` are new.
- **Go API:** `pkg/server.Options.APIKey`, `Server.Close`, `broker.OrderResult.ClientOrderID` and `token.InvalidateRejected` are new. No existing signature changed.

## Fixes and additions

- Add an optional gateway API key (`Authorization: Bearer` or `X-API-Key`), enforced on every route except `/health` and the Swagger UI, with a startup warning when the gateway listens beyond loopback without one.
- KIS raw proxy responses carry `X-Krsec-Cache: miss|hit|stale`. A deduplicated upstream call no longer fails for every waiting request when the request that started it disconnects.
- `GET .../positions?group=true` keeps row order, sums value fields and decimal quantities, and no longer fails to encode when the summed quantity is zero.
- `/accounts/summary` fetches balances concurrently, logs why an account was excluded and names it in the error.
- A rejected token is only evicted if it is still the cached one, so concurrent 401s no longer discard a freshly issued token. Kiwoom now drops a token the broker rejects (error 8005) instead of failing until its recorded expiry.
- Toss token issuance is collapsed per app key; Toss revokes the previous token on every issuance.
- LS never re-sends an order TR after a rejection in the response body.
- KIS paper-trading US sell orders use `VTTT1001U`.
- Token and order-context files are written through a unique temporary file and rename. Rate-limiter names no longer embed the app key, which reached API error messages.
- Background work (startup authentication, KIS symbol reloads, the cache janitor) stops on shutdown.
- Remove comments that only restated identifiers and rewrite the `pkg/broker` documentation.

## Known gaps

Reported by the audit and left unchanged because they need a live account to confirm: Kiwoom `return_code` 20 treated as success for two account queries, Kiwoom total assets possibly double-counting unsettled buys, KIS buying power read from the deposit balance, and single-page reads of KIS balances and open orders.

## Validation

- Full race-enabled test suite with new regression tests for each fix, vet, generated spec checks and OpenAPI consistency.
- Read-only calls against the live KIS, Kiwoom and LS APIs with this build: quotes, balances, positions, account queries, KIS order history with the explicit `tr_id`, Kiwoom paged open-order and execution lookups, and LS overseas candles.
- No live or paper orders were submitted. Order placement, modification and cancellation are covered by mocked providers only.
